Read the flight legs with this in mind

Hub-radius polling only sees an aircraft inside the bubble, so most legs are transits whose real origin and destination were never observed. Those carry NULL endpoints and complete = false — never a guessed nearest airport, because a guessed origin would quietly corrupt every utilisation and punctuality figure downstream.

What this is not

stated up front

A production-grade platform over public data. Engineering cannot make it a full airline data platform, so the boundaries are part of the deliverable:

  • No public API at any price: passenger bookings, crew rostering, maintenance records, fuel uplift, cargo manifests, revenue accounting — all internal systems.
  • Needs paid feeds: published schedules (OAG / Cirium). ADS-B yields actuals only, which is why the mart is named mart_punctuality_proxy and compares each callsign against its own rolling median rather than a timetable.
  • Coverage gaps are real: community ADS-B has no mid-ocean ground stations; satellite ADS-B is commercial.
